## 1. 判据还是计时

- **每轮都会变、且有可靠信号的 → 判据**：协奏满、回路满、技能图标亮、大招能量够、形态图标。
- **长度固定、或者根本没有可读信号的 → 固定时间**：入场动画、过场、"技能起手到伤害结算"（游戏没有"伤害已结算"信号）。
- **最稳的是两者叠：识别到的事件当锚点 + 从锚点起算固定时长**（`hold_for_damage()` 那种）。
- 用反了的两个典型：
  - 把固定长度交给判据：拿"强化重击标记消失"当"重击起手"，标记要到重击整个结束才掉，比出伤晚 3 秒。
  - 把每轮都在变的状态交给计时：post-R 强化态死等 0.8s，强化态那时还没发下来，按下去是空的（7/7 全废）。
- **锚点比窗口长度更容易错，错了怎么调长度都没用。** 用户报的时间是"从按键到出手"，而"检测到到场"比按键晚几十毫秒。
  某一格 A 打不出来，先问锚点对不对（`switch_press_at` / `lib_press_at` 这种按键时刻），再调长度。
- **锚点必须是这个动作独有的状态变化**。先问"除了这个动作，还有别的东西会让它成立吗"——
  珂莱塔强化重击"第1F刷新E2"看着像锚点，可 E 的冷却本来就在走、随时自然好，长按第一帧就"命中"，重击压根没打出来。
- **长度不定的动作**（帧表持续帧 = -1，比如被抬多高取决于 boss 体积的下落）：它后面的固定计时都会抖。
  找不到锚点就把出手时机推到派生窗口靠后（等高度稳下来），每圈多悬一秒，换"每次都一样"。
- **"A到A3"不等于"点3下"**：一律用连点窗口，别数点击数（每下之间干等间隔 + 动画吞掉的那下没人补）。
- **没有「输入缓存」的角色连段按早了直接丢**（帧表角色块里没有这一节）：在盖过派生帧的窗口里反复重发，光调间隔治不好。

## 2. 动画能不能打断（三种，别一概而论）

1. **打不断** —— 按键被吃掉，只能等（变奏入场的 QTE 锁、大招收招）。
2. **能断但会吃掉伤害** —— 必须等到出伤（出伤前按 R / 切人就亏）。
3. **能断而且该断** —— 后摇本身没伤害，主动断掉是提速（落地后 F 处决断后摇、闪避取消重击后摇、A4 一亮就闪避断掉）。

判断依据：帧表的发生帧（伤害判定帧）、派生帧、`可脱手`（√ = 伤害可以脱手、切走不丢）、`中断优先级`、备注。
**帧表里的"发生帧"是伤害判定帧，不等于 UI 信号亮起的帧**，两者没有固定关系。

## 3. 判据设计的硬规则

- **判"消失"之前先确认"出现过"，判"出现"之前先确认"消失过"。** 一天内栽过五次。隐蔽的变体：
  - 进战斗那刻 HUD 还没渲染 → "HUD 不在 = 大招演出开始"0.1 秒假成功；
  - 强化 E 刚放完图标还没灭 → "等第二个 E 亮"立刻通过；
  - 处决动画里 HUD 整个消失 → "发 E 直到图标变灰"当场退出（平时验不出来，只有真打出处决那轮才暴露）；
  - 刚切人那几帧技能栏还是上一个人的 → "按到进 CD"0.2 秒假成功。
  凡是等图标变灰/变亮的循环，**先读 `in_team()[0]` 当门，HUD 不在就什么都不判、只管发键，且只有 HUD 在场时发出去的才算数**。
- **判据只决定时机准不准，不决定做不做。** 读到就用读到的锚点，读不到就按固定偏移估一个，后面的动作一个都不能少。
- **"做完了没有"的检查点放在动作之后**：信号由动作产生时（强化重击攒回路 → 回路满 E 才变黄），在动作之前判就要白打一整轮才收尾。打完留 0.2~0.3s 给资源到账再判。
- **判"技能放出去了"要挑真会变的东西**：消耗资源的技能不上冷却，`has_cd` 恒 False；看资源提示灭没灭，或者 CD 数字跳到这个技能特有的长度（雷引 10s vs 超负荷 25s、普通 E 20s vs 万阙连衡 12s）。
- **提示图标说的是"能不能放"，不是"放完没有"**，只能当入场闸用。
- **判得出来的才判**：强化重击"能不能放/资源被消耗了"能判；"有没有真的打完、有没有命中"判不出来（资源一消耗指示器就灭了，后来被怪打断也看不见）。**判不出来的东西不要去判，让流程不依赖它。**
- **这个信号会自己翻转吗？** 加等待之前先问。绯雪架势图标在最后一刀后根本不会自己灭，要等下一次点击；"每轮都恰好多一下普攻"就是这种提示。只能用计数/帧表决定什么时候走，信号只拿来提前收手。
- **"普攻替换"类机制让"等图标灭"那一侧判据报废**：秧秧羽剑重击后进聆风祀声，普攻被替换，左键图标继续高亮只是图案换了，而框架 `mouse_forte` 模板认的是外圈亮环。排查信号：那一格耗时恰好等于 cap。同一角色另一条分支可能正常，不能拿"某一段验过了"推断整条轴。
- **相邻两步读同一个判据 = 白花一次读屏**（在 ±0.1s 的宏里就是"卡一下"）。前一步返回就绪与否，后一步直接按。
- **"边打边等"的原语先点再读**：`while: 读判据 → 没成立 → 点一下` 会把第一下普攻压到读屏后面（几十 ms 起，肉眼看得出来）。改成 `while: 点一下 → 读判据`。
- **多条判据取或的函数，要能单独看每一条**（拆一个 `xxx_signals()` 返回各路读数，日志里打出来）。

## 4. 读屏信号天生晚：极限轴的提前量

现象：某一格明明做完了，宏迟迟不走下一步；调切人、调间隔、调顺序全没用。慢的不是动作，是确认动作的那个读屏信号（资源条掉下去、标记灭、人升天），它们在帧表里往往挂在动作的中后段。

**诊断（别猜）**：在 trace 里多采样一路信号，用两个信号的时间差 + 帧表反推动作真实时刻。例：
`0.0:00H … 4.5:00H  4.8:10  5.1:10  5.3:10  5.6:00`（forte位+air位+H=HUD不在）——
HUD 4.68 回来那帧 forte 已经是 1，forte 5.6 灭，帧表说清空核心在起手后 0.80s → 重击 HUD 回来后 0.12s 就起手了，后面 0.8s 全是检测延迟。

**改法**：把判据从"它做完了吗"换成"它必然会做"：
```python
# 核心满着 + 手一直按着 = 强化重击必然出手, 不去确认它
if e_sent and full_streak >= FORTE_CONFIRM and live >= MOR_HEAVY_LEAD:
    fired, why = True, 'lead'
```
提前量 = "这一刻到动作真正起手"的下界 × 2 左右；给太小会在起手前就切人。老判据留着兜底，日志记下走的哪条（`lead/air/forte`）。
同类：变身/大招"先确认演出开始（HUD 掉了 = 必然演完），再从按键时刻 + 帧表时长直接走"，不等"回来"那个信号。**滞后因演出而异，要逐个量。**

**不适用**：前置条件成立后动作并不必然发生（可能被打断、资源可能被别的东西吃掉）时，还是要等确认，否则丢了都不知道。

**压到极限时，时间在判据本身里**：去抖最小延迟 = confirm × poll，衔接路径上把 poll 压到 0.01；别为提速把 confirm 降到 1。

## 5. 读什么信号

- **模板优先，颜色只做日志参考**：西仇守那一格颜色"不亮基线"在 4K 上 0.02~0.08，别人 1080p 上 0.32~0.75，没有任何阈值能同时适配；模板在两台机器上一次没错。
  自己的模板：16x16 灰度、只比圆内像素、`glyph_vec`（去均值归一化后点积），嵌在代码里（base64），2K/1080p 逐帧验过再用。
- **颜色非用不可时**：按通道之间差多少算（`b < r-40 & b < g-40`），不用绝对 r/g/b 区间；用 HSV 列占比比 RGB 稳（暗场景 RGB 漏读）。
- **半透明的回路条颜色跟着关卡背景走**（同一条电涌条：教学视频色相 130~139，橙红关卡 157~174）。优先用不透明的白字提示、图标形状、图标整个变灰。
- **图标整个变灰可以当状态判据**（雷主在空中 Q 图标白字占比 0.000，地面 0.06~0.12）。
- **队伍 HUD**：`task.in_team()[0]`；演出/处决/全局时停里不在。看门狗：宏里 HUD 连续很久（比最长演出还长，8~9s）没出现就整圈放弃。
  看门狗只认 `hud_ok()` 刷新的时刻，**纯计时、不读屏的长段（点 A 连段 + 按住重击）加起来超过 HUD_LOST_ABORT 就会被当成关卡结束、每圈结尾整圈扔掉** —— 段中间找个不影响节奏的空当（闪避后、接普攻前）`next_frame()+hud_ok()` 喂一下（嘉露莫 10-16 干跑：嘉贝爆发 8s+收尾 1.7s）。
- **技能 CD**：`task.get_cd(name, index)` 读到负数 = 不在 CD，先 `max(0, cd)`；真正的误读（7.2 读成 72）按上限另判。读到过一次满的协奏会被角色缓存。
- **协奏**：`task.get_current_con()`，0.99 是哨兵；`stall_give_up`(1.2s) 比伤害结算短，收尾要变奏的地方放到 2.0 或分两段（先 ≥0.85，放完声骸再等真满）。干等等不来就**边点普攻边等**。
- **处决**：只认屏幕中间的 F 提示（`find_one('f_break', box_of_screen(0.2,0.2,0.75,0.8,...), threshold≥0.90) and not is_pick_f()`）；顶部谐度满（`f_break_full`）比提示早好几秒。`check_f_break()` 中央那路有 1 秒频率限制，宏里自己补。
  **但要看 Boss**：心汐守那只 Boss（手打和实机按 F 都真处决了）中间提示模板一次都没认出来，只有顶部谐度满认得出，那条轴两样都认。不管认哪样，**都别只在出手那一刻看一帧**：前面那几下普攻期间每帧都看、见过就记下，出手时再读 3 帧确认（心汐守 10-07 只看一帧，三圈全漏）。**谐度满的时刻也跟着输出走**：同一条轴实机里处决提示出在插段/第一段/别人身上，跟攻略视频不在同一格 —— 要处决的角色在场的每一段都要看，别只挂在视频那一格。
  **变奏入场的镜头会把中间提示甩出框**（嘉露莫 10-16 实机，4 次变奏全漏）：入场那 1 秒多中间提示置信度掉到 0.55~0.70，到场 +1.05~1.45s 才回到 0.95；顶部谐度满（boss 头像外圈）不跟镜头走、一直 0.98~0.99、2K/1080 一致，**处决打完才清空**（教学视频 182.4→182.7）。
  写法：入场时外圈满着（或切人前上一个人身上读到过提示）就一直盯中间提示到到场 +2.0s，见到才按 F；按完提示连 3 帧不见才算起手（提示单帧会掉到 0.85~0.88），还在就隔 0.3s 再按；等完动画提示还在 = 没处决上，再来一轮。没外圈也没见过提示就只读 3 帧，不白等。
- **阈值拿实机日志定，别拿视频定**（视频里"不亮"是硬 0.00，实机 0.02~0.04）。
- 自算框 `box_of_screen_scaled(3840, 2160, ...)`；攻略视频游戏区常不是全屏，从视频换算的框不算验证过，要回实机录屏核。

## 6. 保底：什么能加、什么不能加

用户原话（2026-09-22）："宏的流程都是没问题的，都是实机检测过的……让你加了保底你就开始做不好了"。

- **只花时间的 → 默认开**：切人确认/补按数字键、等入场、等收招、大招连发（落在 CD/演出里是空操作）、纯读屏、HUD 看门狗。最坏后果是这一轮慢一点。
- **会改游戏状态的 → 默认关**：补按技能键、额外点普攻（耗资源/推连段）、多放一次技能。判据一误判就把本来对的流程搞坏，而且外表看不出来。
  踩过的：秧秧"1苍没打出来就再 E+长按"—— 每按一次 E 就翻一次剑式，奇偶打乱后面全错位。**少打一发，远好过打错一发。**
- **判据分辨力不够时尤其不能驱动改状态的动作**（读的是"≥1"而不是"满2"，拿它判"E 生效没有"等于瞎猜）。
- **补救那一发的上限要比首发短**（首发 1.2s / 补救 0.4s）：首发等满上限还没成立，多半是前提真的不满足（资源没攒够），补按救不回来。
- **"必须打出来"的关键步骤**由用户点名（心转相、穗穗醒春潮、穗穗三段回路不满不许 QR）：这类才用"补到出为止（上限放长）"，每轮看状态决定按什么，并防止补过头（连 3 轮看不到转相图标 = 已在照世相，再按 R 会放成借相）。
  - **后面的计时要从"起作用的那一下"算时，补按必须一按一看**（2026-10-08 绯洛穗醒春潮，干跑抓到）：每按一下要拿到**至少一帧 HUD 在场**的读数才决定补不补，HUD 不在就等、不按。否则看不见期间补的那一下出了手，回来时只能记在最后一下头上——那次差了 0.42s，正好把窗口只有 2.4~3.0s 的落地 E 推进失败区。
  - **"长按多久"的松手判定窗口要拿录屏逐帧量，帧表只当参考**（2026-10-08 绯洛穗，洛瑟菈长按 E）：帧表写
    30~45F / 60F 后成功，照着改成 1.2s 实机两次全失败；录屏里聚焦环只在按下后 0.86~1.10s 是金色（完美焦距），就这一段。
    以前拿"E 进没进冷却"当成功判据去标定，失败（补光）也进冷却，分不出来 —— 成功判据必须能区分两种结果：
    她的补光会让 E 冷却当场减 8s，所以松手后读冷却 ≥11 = 成功、个位数 = 失败。窗口只有 0.24s 宽时，按住要用切片
    `time.sleep` 精确计时（执行器 sleep 每 0.4s 插一帧截图，会多睡几十 ms）。表现是"对焦时好时坏"，用户会以为是网络 ping。
  - **删掉"看着多余"的动作之前，先看它是不是碰巧在替后面那步等时间**（同一天，洛瑟菈）：旧代码每次 E 后误判"被吞"又白按一下 E，
    这一下正好多等了 0.8s；去掉以后 R 在松手后 0.04s 就按了，而追光的印象 0.9s 后才到账。再加上"按过 R、图标暗着 = 放出"
    这个判据（图标从来没亮过，本来就暗），R 没放还白打了 8 秒变身段。放出要认"HUD 消失"或"亮着的时候按过、之后变暗"。
  - **"等协奏满"的计时要从 HUD 回来算，不从动作结束算；补打时按住期间也要逐帧看**（同一天，洛瑟菈变身后）：变身段打完有段
    隐藏 HUD 的收尾演出（~1.4s），HUD 回来时环 ~0.83，0.2~0.3s 后自己补满。旧写法从变身结束起等 1.5s，三次都差 0.01~0.12s
    超时，接着先打一整拍 0.6s 重击才再看 → 用户看到的是"还要 A 一下才切"。写法：记"最后一次看不到 HUD"的时刻，从那里等，
    补打时按住期间逐帧看，一满就松手交棒。
  - **"HUD 消失 = 大招放出"要看持续时间，不能只看两帧**（2026-10-12 绯洛穗，洛瑟菈）：大招隐藏 HUD 4.5s，特效挡数字牌一两帧就能让
    `in_team()` 连读两次 False。那次松手后 0.39s 就判"放出"，之后不再按 R。改成连续 0.5s 才算，放出时刻记消失那一帧，后面的等待从那一帧算。
  - **"一亮就按"之前先想：早按会不会打断正在给资源的那个动作**（同一次）：剩照片时 R 能在追光中途放出，追光那 20 协奏就没了，
    下一个人没变奏。资源比早 0.5s 重要，按键窗口从"资源到账"那一刻开。
  - **变身类状态会跟着角色下场、下次上场还在**（同一天，洛瑟菈追忆状态）：变身段没收尾就切走，下一轮回来 E/R 都放不了，
    代码按 E 只看到"冷却读不到"。每个"放了大招进形态"的角色都要想：① 所有出口（包括超时退出循环那条）都把形态打完；
    ② 上场第一下技能没反应时，先按"还在形态里"处理（照形态的收尾方式打完）再走正常流程。
  - **按住鼠标的轴里，补按间隔不能照点普攻的轴抄**：心雷穗开场是点普攻，醒春潮 0.05s 连发没事；绯洛穗全程按住左键，`send_key` 每发都投 `WM_ACTIVATE` 会把按住松掉，改成"按一下等 0.4s 反应，还亮才补"（正常情况仍然只按一次）。
- **被怪打断的通用补法：到上限没出去、图标【还亮着】就等 HUD 回来再按一轮**（嘉露莫 10-17，用户要求关键技能被打断也要放出来）。R / 有 CD 的 E / 声骸 Q 在冷却/没能量时按了什么都不发生，所以"亮着才补"不会多放一次；补之前图标连 2 帧亮、HUD 在场。R 补两轮（每轮 1.5s），E/Q 补一轮（1.0s）。
  **按住类（观测普攻循环这种"按住等条件"）被打断**：倒地起来游戏可能不认还按着的左键，出炮/协奏都等不来。判"根本没在打" = 出炮撞上限时协奏比按下时一点没涨（<0.02），不用再等协奏上限、直接松开重按一次（省 3s）；按住蓄力/派生类的照旧绝不重按。
  **按住/连点攒资源时丢目标**（锁散维 10-26）：怪被打死、换波后宏里没人重新锁目标（框架 `target_enemy` 只在宏外跑），按住的左键过场后也不接连段，人站着撞上限、协奏 0.00。每 0.1s 读一次有没有怪（`is_boss()`/`has_health_bar()`/锁定图标任一，Boss 挑战锁定图标读不到），连 3 次没有 → 松手、HUD 在时每 0.3s 中键等新怪（等的时间不算上限）→ 读到再按住；怪还在但打不到 = `get_current_con()` 2.5s 没涨 0.03 → 松开 + 中键 + 重按。实现见 `Sanhua__Suoming__Verina/Suoming.py` 的 `so_enemy_tick` / `so_stall_tick`。
  **只靠计时的那一格先找一个"做完了会翻转"的条**：露帕破敌原来是 R 后计时 3.6s，录屏里狼焰条 HUD 回来就满、破敌那一帧清空、不闪 → 改成点到条清空（被打断就接着点，上限到破敌窗口尾），条读不到退回计时。
  **派生窗口被打断丢了 → 去技能文本里找一个不靠窗口的输入补**（嘉露莫 10-17 00:38）：露帕"短按出锐爪"只在焰袭后一小段时间有效，被怪打断后短按到上限也没有第二个狼魂 → 没强化E → 下一个人不是变奏进来，整圈连锁塌掉。nanoka 原文里**长按重击**在狼焰≥50 时照样给狼魂（有 1 个 = 锐爪、0 个 = 狼咬），就拿它补：资源条满才长按（框架原生写法也是这样），不满点 A 攒，图标亮就停；补的那一格上限比短按阶段短。
  **大招没能量（图标暗着）别直接放弃这一棒**（嘉露莫 10-17 09:19）：怪换波时变奏那一下没打中，R 差一点能量，旧写法点 1.5s 就切 → 后面整圈靠 R 解锁的东西（破敌/沸腾/狼魂/强化E/下一个人的变奏）全塌。改成点普攻攒到 R 图标连 2 帧亮再放（上限 6s，攒不满才放弃）。**攒能量只用普攻**：技能也回能量，但会进冷却，换成强化版之后吃不吃冷却技能文本常常不写，不能拿后面那发关键强化技能去赌。
  **会改状态的盲补要有"读到过"守卫**：判据本身读不到（图标模板认不出）时，"没见到 → 补"每圈都白补一次。记一个"这个图标读到过没有"，从没读到过、又已经补失败 N 次（取 2，别取 0 —— 启动轴那一次补可能是合法的）就停补，日志写明原因。
- **"被打断就放弃这一步"也是一种保底**（卜灵卦象被打断就直接开 R，不去补卦象；补救狂 A 7 秒反而把后面全推歪）。用户会告诉你哪些步骤宁可放弃。
- **"没怪先别切"（等新一波再交棒）只是某些轴的需要，不是通用保底**（2026-10-08 用户：角色技能机制不同、轴的需求也不同，不能套用）。
  加过的两条：绯洛穗、心卜穗，都是上一个人的大招清了这一波，下一个人变奏入场那一下打空，**命中才给的资源**（穗穗 QTE 约 47 协奏）没拿到，后面整圈都缺协奏。
  做法是 `target_visible()` 连 2 次读不到锁定目标 → 不 A、每 0.3s 中键锁目标、最多等 4s、等不到照切（整场打完）。
  加之前先问三件事：①交棒后那一下是不是"打中才给"（nanoka 技能文本里看"命中后"）；②等的这几秒会不会把有时效的东西耗掉（濯雨时、buff 窗口、某人要在某一刻在场）；③用户有没有说过这一格要卡时间。拿不准就问用户，别默认加。
- **结算/过场**：drive 入口 HUD 1.5s 不在就不动；"带变奏上场就从这段接着打"只认刚切进来几秒内的（`last_switch_in_time`）；看门狗。
- 每条保底分支都要在干跑里有一个 `DRY_FAIL` 旋钮让它至少跑一遍。

## 7. 循环与上限的形状

- **分轮 + 每轮超时 = 被打断几次就把预算耗光**，然后再也不做那件事。改成一个从头跑到尾的循环：每一帧都看信号，亮了就做，退出条件只看目标状态，只留一个总预算防判据失灵。
- **等待类的收尾也要继续检测**，不能退化成干点普攻（"最多点 8 秒普攻"全程不看提示，强化重击好了也白瞎）。拆成一秒一段，每段"打普攻 + 盯提示"。
- **只能按时间的格子把 cap 压到接近实测值**（实测 0.8s 就别给 2.5s），判据失灵时损失才小。
- **用"状态亮了"当收尾信号**，别写死打几轮（被打断一轮就错位）。
