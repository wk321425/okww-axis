# 实机报问题：症状 → 先查什么

**第一步永远是读这局的记录**：先 `run_report.py summary / around` 读跑轴记录（`references/axis-recorder.md`，按键、判据读数、在场、代码位置都在里面），
再看 `working/logs/ok-script.log`（timeline / trace / 采样），画面先看记录里的低清帧和 F8 原图，不够再要录屏，最后才动代码。
连改三轮常量都落空、一读 trace 当场锁死的事发生过不止一次。下表「先查」那一列里的日志标记，跑轴记录 `around --kinds log` 里也有。

| 用户说的 | 先查 | 常见根因 |
|---|---|---|
| 自定义轴完全没生效 / 跑的是内置轮换 | grep `loaded chars success`、自己的 entry 标记、界面 Chars 栏 | 队伍认粘了（置信度跨局一模一样，重启 ok-ww）；目录名排序/类名错（上游改名）；三个 .py 少一个；UI「重置为内置」覆盖了文件 |
| 开关自动战斗后不从头跑 / 从循环轴中段开始 | 日志 `opener not pending (already armed-down ...)` | 没有 enable 监视线程，或只在 `reset_state` 里启（粘性复用时不跑） |
| 一直重跑启动轴 / 循环轴轮不到 | 日志形状 `R_fired@36.52` → `target lost` → `enter combat` → `opener entry` | 宏在大招演出里把控制权还回去；`BaseChar.sleep()` 把 `skip_combat_check` 关掉了 |
| 结算画面上还在乱按 | `drive` 的 HUD 检查、看门狗 | 缺 HUD 看门狗；"带变奏上场"没限制在刚切进来几秒内 |
| 某一格"慢了/不能第一时间切人" | trace 里多路信号的时间差 + 帧表 | 确认信号天生晚 → 充分条件 + 提前量；或者被游戏换人 CD 拒了（trace 一串旧 index） |
| 回放总时长比宏表短 / A 没打出来 / 连段少一段 | timeline 里每格耗时、`A x0` | `task.click()` 10ms 被吞（改 `tap`）；`macro_spam` 的 `max_clicks` 提前结束窗口；没有输入缓存的角色按早了 |
| 那一下没打出来（紧跟切人/变奏/大招） | 那一格的锚点和耗时 | 落在入场 QTE 锁/收招里被吞 —— 分两句写、先盖动画再递出；大招后留 ~0.8s 收招 |
| 技能"放了"但其实没放 / 后面整段错位 | `_ok` 是不是 0.1~0.2s 就成立 | 刚切人技能栏还是上一个人的、HUD 本来就不在（fire_r 假成功）—— 先见过亮才认暗、按 R 前等 HUD |
| 切人后"多了个跳A" / 开场普攻给的资源不对（卜灵给了震没给艮） | `run_report.py sheet` 看切人前后那两秒下一个人是不是在空中出现（低清画面就看得出，不用录屏）；上一个人切走前最后一个动作 | **切人落在上一个人离地的那一下，下一个人就是空中进场，开场普攻变成下落攻击**（心卜穗 10-09：心照世相普攻、穗穗强化 E 都会离地）。凑时间别用会离地的普攻，站着等；下一个人开场普攻要读结果，下落了就落地再补。框架 `flying()` 靠控物图标，没装控物的人用不了 |
| 没满协奏就切了 / 差一丝丝 / 下一个人没变奏 | 协奏采样序列 | 用了 0.99 当门槛；`stall_give_up` 太短；读了角色身上缓存的"满"；环快满时 1.00 也会早(连 3 帧都会)，要靠动作量保证（framework-pitfalls.md） |
| 协奏干等不涨、角色愣着 | 采样一直是同一个值 | 伤害早结算完了，干等等不来 → 边点普攻边等；或者前面少打了攒协奏的 A（用户链数/练度跟作者不同） |
| 处决从来不放 | `F_none` | `check_f_break` 1 秒频率限制 + 宏里不刷新 `can_break` → 自己读中央提示 |
| 放了处决后直接切人/流程乱了 | 处决前后的判据 | 处决动画里 HUD 消失，"图标变灰"判据当场成立；"HUD 消失"被误判成技能出手 |
| 连点打到 A4（或第 N 段）再接技能，只在处决过的那圈没打出来 | 时间轴 `…处决(F x1,1.55s)` 后面那个技能离处决完不到一整套连段 | 处决完连段从 A1 重来，引擎 `a_until(breaks=True)` 只把 deadline 顺延处决花的时间，处决前打到的段数白丢了。靠连段打出某一段的窗口要按「处决完 + 整套连段到那一段」重新计时（卡夏釉 v0.1.5 给 a_until 加了 `restart` 参数：小卡 A1 17F+A2 46F+A3 60F=2.05s 起 A4，处决完 2.40s 才按 E） |
| 长按/蓄力没起来 | 是否在按住期间调了 send_key / mouse_down / click、是否重发按下 | WM_ACTIVATE 打断；蓄力类重发 = 连点；抄来的"松开重按"把需要连续按住的派生打断 |
| 某一格耗时恰好等于 cap | 那个判据另一侧会不会翻转 | 普攻替换/形态切换后图标继续亮；信号要等下一个动作才翻转 |
| 加了保底之后流程反而坏了 | 保底改没改游戏状态 | 补按技能翻了形态/剑式奇偶、额外普攻推了连段 → 改状态的保底默认关 |
| 切人超时、之后全乱 | `switch ... timed out` + trace | 演出里 HUD 不渲染（先等 HUD 再切）；被击飞/硬直（重试）；超时后假装切过去了（要按实际记账或整圈放弃） |
| 2K 正常、别人 1080p 不正常 | 自算框和颜色阈值 | 写死像素、颜色基线漂 → `box_of_screen_scaled` + 模板 |
| 别人那边第一圈 TypeError 停任务 | 报错的方法名 | 对方版本改了内置方法签名 → 签名适配层 |
| 怪刷得慢时脱战重来 | FStartCombatTask 日志 | 不脱战保护没挂上（`补丁已挂上`）；执行器没起来（`start execute`） |
| 启动轴打完交回框架那一下愣 ~1s（之后各圈之间不愣） | 日志 `F 开始战斗: 10 秒还没锁到目标` + `target lost try retarget` + 一串中键 | 宏从不锁怪，按 F 开打后一直没锁上，保护期（10s）一过框架就补锁；刚演完大招还在收招时中键不生效，要连点好几下（卡夏釉 10-28 点了 5 下、0.88s）。启动轴中段角色正常出招时读一眼 has_target/no_target 图标，没锁就点中键；别直接调 `has_target()`，它有一条修熊声骸的分支会 sleep 1s 还会按 esc |
| "资源明明满了还不放" / 指示比资源晚亮一截 | 用挑战倒计时（游戏时间）量 上一发 -> 这次指示亮 | **隐藏冷却**：技能文本里"每 N 秒可激活"（弗洛洛谱曲终末 25s），按游戏时间走、大招演出时停，墙钟上长一大截（25s→~39s）。指示=资源+冷却，这时提前按出来的是普通版；资源再攒快也不缩圈 —— 先去 nanoka 读全文、拿倒计时量，再决定改不改 |
| "比手打慢好几秒" | 按某个对齐点（守 R / 第一次切人）逐段对表游戏秒 | 一段一段找差在哪；常见：多余的确认等待、打空（没贴怪资源不涨）、少了作者的位移（W+前闪） |

## 对表的方法

1. 找对齐点：两边都有的明确事件（某人的 R 出手、第一次切人）。
2. 逐段列：作者/手打 vs 我们，每段的游戏秒（扣掉演出时停），差值。
3. 只盯差值最大的一两段，看那段的 timeline 标记是判据成立还是撞 cap。
4. 改之前跟用户确认"这一段的目标是什么"（攒资源？等 buff？位移？），别按伤害去理解攒资源的格子。

## 别做的事

- 别在没读日志的情况下改常量。
- 别改 `src/` 修框架的毛病（更新会被盖回）；写在队伍文件里绕过去。
- 别把用户没点名的那条轴一起改了。
- 别把录像里的手滑当轴抄。
- 窗口切走 / 丢目标（`target lost` + 窗口 `visible:False`）导致的崩不是轴的问题，告诉用户就行。
