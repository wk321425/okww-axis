## 1. 先判断视频类型 → 墙钟用什么

| 类型 | 墙钟 | 要防的 |
|---|---|---|
| 剪辑攻略/教学 | **游戏倒计时**（`MM:SS:CC`，CC 是百分秒） | 变速剪辑（0.25x~1.0x 混着）、整帧定格打字幕；大招演出/处决时停里倒计时也停 |
| 教学视频里的「完整演示」章节 | 往往是唯一不变速不定格的一段，视频时间可直接当墙钟 | 这类常把 HUD 关掉，倒计时读不到；先用手速判倍速（同一个人连点间隔 0.13~0.20s 是正常） |
| OBS/DVR 直录 | **视频时间本身**（左下角系统时间戳/水印跟视频 1:1） | 游戏倒计时在时停里会停（120 秒的局只走了 ~107 秒），别用倒计时 |

**要就要一版不变速的**：变速剪辑能扒出顺序，扒不准时机。时机只能靠倒计时 + 每格单独判倍速，或者让用户实机一格一格试。

## 2. 标准流程

脚本：`scripts/video_tool.py`（自带 python 跑）。所有坐标是视频像素。
解码默认用 ffmpeg（`F:\ok-ww\tools\ffmpeg.exe`，找不到才退回 cv2 顺序解码；`--decoder cv2` 强制旧路子）：
`frame`/`sheet` 直接跳到那一秒（290 秒处取一帧 0.5s，cv2 要顺序解 15s），裁剪缩放在 ffmpeg 里做完，`freeze`/`sheet` 快 10 倍左右。

```bash
PY=F:/ok-ww/data/apps/ok-ww/python/python.exe
T=~/.claude/skills/okww-axis/scripts/video_tool.py
$PY $T info "E:/轴视频/xxx.mp4"                       # 分辨率/fps/时长
$PY $T frame "E:/轴视频/xxx.mp4" 160 -o f160.png      # 整帧看布局(字幕在哪、有没有浮层、游戏区是不是全屏)
$PY $T freeze "E:/轴视频/xxx.mp4" --start 20 --end 90 # 定格区间(算时长要扣)
$PY $T keys "E:/轴视频/xxx.mp4" --layout layout.json --start 151 --end 201 -o keys.csv
$PY $T slots "E:/轴视频/xxx.mp4" --boxes "x1,y1,x2,y2;...;..." --start 151 --end 201 -o slots.csv
$PY $T ocr "E:/轴视频/xxx.mp4" --crop 1030,135,1165,172 --step 0.2 --countdown -o cd.csv
$PY $T sheet "E:/轴视频/xxx.mp4" --start 170 --end 176 --step 0.1 --crop 1560,925,1870,995 --scale 2 --cols 6 -o s.png
$PY $T cuts "E:/轴视频/xxx.mp4" --start 40 --end 240 --countdown cd.csv -o cuts.csv   # 剪辑点 + 倒计时断点 + 每段倍速
```

顺序：`frame` 定位 → `freeze` 找定格 → 一遍全片扫描（keys + slots）+ 一遍 OCR（倒计时，必要时字幕）→
`cuts --countdown` 把视频切成"游戏时间连续"的几段（每段倍速也有了）→
关键几秒用 `sheet` 拼长图人眼确认（技能栏图标形状、CD 数字、字幕）→ 把各路时刻换算成游戏秒。

**`cuts` 的读法**（2026-10-16 弗洛洛 4a8 赫教学视频 40~240s 实测）：
- 画面剪辑点（PySceneDetect AdaptiveDetector）在打斗片里假阳性很多：大招特写、闪光、字幕卡都算。27 个里只有 8 个跟倒计时断点对得上。
- 倒计时断点比画面准：同场景接着剪（回放上一段、剪掉几秒）画面差只有 5 左右，PySceneDetect 看不出来，倒计时一跳就露馅。
  画面剪辑点可能比真断点晚 0.4~0.7s（剪辑后紧跟着一个大动作），所以两者 ±1s 内算同一个。
- 每个断点两侧各量一次倍速（两两斜率中位数）：`[0.40x]` 就是慢放、`[0.00x]` 是定格或时停。按 1 倍速硬推会把慢放误判成剪辑。
- "倒计时多了 Ns" = 回放/换了另一段录像（教学视频常把同一段放两遍讲）；"剪掉了 Ns" = 跳过了一段。<1s 的标了"可能是错读"，拿 `sheet` 看一眼倒计时。
- `ocr --countdown` 的 `kept` 列（全片最长非增子序列）**在多段拼接的视频里会把别的段整段扔掉**；`cuts` 用的是全部读数，自己做局部清洗。

- `sheet` 一张图读几十帧比一帧一帧 Read 省得多；倒计时、技能栏 CD、字幕都可以这么人眼读。
- 帧图放会话 scratchpad，定稿时删掉。
- 先在一帧上把关心的颜色像素的 x/y 直方图打出来再定位（步骤条的黄竖条是孤立的一列，按"整行找黄"会命中行内头像的黄圈）。

## 4. 各路信号的读法与坑

- **键盘浮层**：唯一能分清"E 和 R 谁先按""长按还是连点"。真长按读数稳定 1.00 且两端干净跳变。
  - 画面泛黄（变奏闪光、大招特效）时几个键同时判黄 → 同一帧 ≥3 个键黄就整帧作废（脚本已做）。
  - **定格期间浮层一直亮着**，一次点击会读成按住几秒，先扣定格。
  - **作者压暗画面做高亮的那几秒浮层会漏键**（心雷穗循环轴 2A 之后的普通 E），关键几秒拿技能栏 CD 交叉核对。
  - 左键连续亮十几秒不一定是浮层卡住，可能真的一直按着（景燃那段），对照技能栏 CD + 回路条提示逐帧读。
- **头像数字牌**：在场的那个没有数字牌 → `gray>190` 占比最小的是在场。比字幕可靠，精确到帧。
  手机演示只显示两个场下角色；切人 CD 期间头像被灰色遮罩盖住，那段别自动扫，抽帧人眼看。
- **倒计时 OCR**：`from onnxocr.onnx_paddleocr import ONNXPaddleOcr`，**必须 `use_openvino=True`**（没装 onnxruntime）。
  清洗用**最长非增子序列**，不要用局部中位数（会把连续 5 秒正确读数整段误删，插值把 1.31s 算成 0.58s）。常把 `01:53:66` 读成 `0:53:66`（丢分钟位），脚本借上一条的分钟补。
- **技能栏 CD 数字**：PP-OCR 能读，连续递减一段的起点 = 按下时刻，首个读数 = CD 总长。**CD 突然跳变**能定位"换形态/换了另一个技能"。CD 在时停里冻住不动 —— 反过来正好是识别处决/时停窗口的判据。
- **技能栏图标形状**：人眼逐帧看形状能读出技能状态机（今汐 E 普通→突进→惊龙破空）；但**自动判亮度不行**（特效一闪整块都亮）。
- **字幕**：作者逐步解说 = 手写轴。裁出来每 10 帧一条和倒计时并排拼长图一次读 40 条。别用"白色像素面积变化"自动切段（背景一堆白）。**改轴前先整句读字幕**，别只看关键词。
- **HUD 提示的含义别只凭教学视频下结论**：作者手快时"满了就亮"会被看成"按了才亮"（雷主 [E] 小框）。拿用户实机录屏看一次"满了但还没按"的帧再定。
- 今汐大招会把场景整个换成天空 —— 这类"画面特征"也能扫出技能释放时刻。
- **cv2 按 `CAP_PROP_POS_FRAMES` 跳帧会偏**（拿到的是早 ~22 帧那一帧），cv2 后端全部顺序解码（脚本已做）。ffmpeg 后端用 `-ss` 精确跳帧，时间 = PTS − 文件起点（播放器里看到的时间）。
  2026-10-16 实测心雷穗 DVR（2K60，开头无空档）：PTS 和 帧号/60 全片差 ≤2ms，两个后端同一时刻取到同一帧。开头有空档的文件（以前见过 ~0.417s）两者会差这个空档，以 ffmpeg 的为准。
- **颜色：cv2 按 bt601 转 RGB，ffmpeg 按文件标的 bt709**（DVR 标的是 bt709）。同一帧两者平均差 3.4，R/G 偏 2~3。ffmpeg 的更接近游戏原画面；以前用 cv2 抽帧标的颜色阈值可能偏了几个单位，贴着阈值的要重标。
- ffmpeg：`F:\ok-ww\tools\ffmpeg.exe`（gyan 7.1 essentials，从 `E:\视频制作\*\tools\bin\` 拷的）。`D:\Bili23 Downloader\bundle\ffmpeg.exe` 是精简版（没有 image2/滤镜不全），脚本会自动跳过它。
- **`--crop` 坐标别用奇数宽高（2026-10-25 已修）**：yuv420 的片子 ffmpeg `crop` 会悄悄把奇数宽高/坐标舍成偶数，输出每帧比 `ow*oh` 小，
  按字节切帧就错位、时间戳一帧帧往前漂（心锁守 11w 视频 `ocr --crop 1030,140,1160,175` 从 35s 扫到 170s 漂了 3.9s，倒计时和头像牌全错位）。
  `video_tool` 现在加了 `exact=1` 并校验 ffmpeg 报的帧尺寸，对不上直接报错。之前用奇数框扫出来的 `ocr/slots` 结果要重扫；`keys`/`sheet` 不受影响。
- 长风ei 心锁守 11w 轮切视频（1920x1080）：倒计时 `1030,140,1160,175`；头像牌 `1729,200,1761,232` / y+113 / y+225（1 号位心、2 锁暝、3 守）；
  键盘浮层 `1=(335,718) 2=(393,718) 3=(450,718) / QWER y=773 x=334,393,447,507 / ASDF y=829 同列 / 空格=(390,880) / 左键=(600,726) 右键=(674,726)`，半宽 14。
- `cv2.imwrite` 写不了中文路径，用 `imencode().tofile()`。
- **DVR 开头解码失败**（h264 `non-existing SPS`，`video_tool` 报"没读到帧"、顺序 `read()` 第一帧就 False）：先 `set(CAP_PROP_POS_FRAMES, 300); read()` 热身，再跳到目标帧顺序读；
  这种文件 `POS_MSEC` 比 帧号/60 大好几秒，**按 `POS_MSEC` 标时间**，跟左下水印墙钟对时（2026-10-12 弗坎莫录屏）。
- 视频文件名里可能有**两个连续空格**、`【】&` 之类，手打路径对不上会报"打不开视频"，用通配符 `ls *关键词*.mp4` 取真实路径。
- 教学视频的字幕整片扫一遍很快：`ocr --step 0.4 --crop <字幕带>`（不加 `--countdown`），相邻相同的合并，15 分钟片子 ~2 分钟出 500 条。

## 5. 宏截图怎么读

手机宏工具导出的表：三列 按键 / 动作（矮图标=按下，高图标=松开）/ 延时ms，一张图常拆成几块滚动截图。

- **延时是"这一行之后"等多久**：按下行的延时 = 按住时长，松开行的延时 = 到下一项的间隔（R 松开后 3680 = 大招演出）。
- **末行 9999 = 这段宏结束、接下一步**，不是停手。
- 行是成对的（同一个键按下紧跟松开），抄完先脚本校验配对，再算累计时刻去和视频切人时刻对表（卡夏千三段宏误差都在 0.05s 内 = 读对了）。
- 分页截图**页间不重叠**的判断：拿边界上的成对按键去重/不去重，看哪种跟另一条宏对得上。
- 截图上"下图对应队伍顺序千夏卡，用于 XX 要把 1 和 3 对换"→ 数字键翻译成按角色切人。
- 延时 0 的按键回放时至少按住 10ms 以上（PostMessage 太短会被吞），超出部分从后面的间隔里扣，不推迟下一项。
- 两条宏常常只差几格（龙凤维启动宏/循环宏 34 格逐字相同），先 diff 再写，手动段写一份。
- **照抄别人的宏时，前置状态可能不同**（多了手动段 → 协奏满了 → 同一格从普通入场变成变奏入场带 QTE 锁）。

## 6. 用户实机录屏怎么对日志

**排查实机问题先用跑轴记录**（`references/axis-recorder.md`：自带时间，不用对时）。这一节是记录不够时才用的：定新判据没有 F8 原图、出事落在轴没取帧的空档、要逐帧（60fps）量时序、做视频、对方没装插件。

- DVR 原片 `E:\录屏\Wuthering Waves\*.DVR.mp4`，**文件名 = 录像结束时刻**，往前推片长就是开始时刻；左下角常有墙钟水印（直接看）。用户剪的 720p/1080p 版放在 `E:\轴视频\`。
- 先在日志里找这局的 entry 标记和 timeline，再在录屏里找开局（第一下切人 / 第一发大招）对齐 t0，然后逐段对表：手打/作者视频 vs 我们，每段差多少游戏秒。
- 用户的录屏也是验证 2K/1080p 读屏框的素材：同一帧原图和 `cv2.resize` 到 1920x1080 各读一遍，读数要一致。
- 录屏里"多出来的动作"（停顿、多余的 A）先问用户是故意的还是手速。

## 7. 产出格式

逐格表（写进持宏者 docstring 的「轴的形状」，详细版写进 memory）：

```
启动轴: 穗穗 3A(1.2s) -> 醒春潮 -> 0.07s 切雷主
        雷主 E(雷引) -> 空中 A(下落) -> 落地 -> 切穗穗(到场 2.2s)
        穗穗 A 到三段回路满(3.9s) -> Q -> R -> 演完 -> 变奏雷主
循环轴: ...
每格: 时长(游戏秒) / 判据 or 计时 / 判据是什么 / 视频出处(秒)
```
